## Спајање табела (JOIN) и вишеструке релације

### Типови спајања (JOIN)

- `INNER JOIN` (или само `JOIN`) 
    - Враћа само оне редове који имају поклапање у обе табеле
    - На пример, само играче који имају забележену статистику
- `LEFT JOIN`
    - Задржава све редове из "леве" (тј. прве) табеле, чак и ако нема поклапања
    - Тамо где нема поклапања, систем убацује `NULL`
    - Кључно за проналажење података који "недостају"
- `RIGHT JOIN`
    - Иста логика као `LEFT JOIN`, али задржава редове из "десне" табеле
- `CROSS JOIN`
    - Спаја сваки ред из једне, са сваким редом из друге табеле
    - Стварајући тако све могуће комбинације (Декартов производ)

### Алијаси (Таблични псеудоними)

- Када радимо са више табела, користимо кратка имена (нпр. `matches m`, `players p`)
- Овако добијамо јасно значење из које табеле долази која колона 
    - Притом пишемо краће: `p.first_name` уместо `player.first_name`

### ON и WHERE код `LEFT-JOIN`-a

- Услови у `ON` клаузули одређују како се табеле спајају пре него што се додају `NULL` вредности
- Услови у `WHERE` клаузули филтрирају крајњи резултат након спајања
- Погрешно постављање услова у `WHERE` може претворити `LEFT JOIN` у обичан `INNER JOIN`

## Решења задатака - Први део

1. За утакмице сезоне 2024/25 прикажите датум, име судије и његову националност. Колико редова очекујете? Која националност судија се најчешће појављује?

```sql
SELECT m.kickoff_ts, r.referee_name, r.nationality
FROM matches m 
JOIN referees r ON m.referee_id = r.referee_id
WHERE m.season = '2024/25';
```

Ово је стандардни `INNER JOIN`. \
Повезује табелу утакмица са табелом судија преко њиховог заједничког кључа (`referee_id`)

2. Прикажите клубове и њихове стадионе са капацитетом. Колико редова враћа INNER JOIN, а колико LEFT JOIN? Који клуб има највећи стадион (order by)?

```sql
SELECT t.team_name, s.stadium_name, s.capacity
FROM teams t 
LEFT JOIN stadiums s ON t.stadium_id = s.stadium_id
ORDER BY s.capacity DESC NULLS LAST;
```

Користимо `LEFT JOIN` да бисмо задржали све тимове.\
`NULLS LAST` осигурава да се тимови без стадиона појаве на дну приликом сортирања.

Чим питање наговештава да неки клуб можда нема стадион, обичан INNER JOIN би тај клуб обрисао из резултата.\
Да бисмо приказали све клубове, морамо почети од табеле клубова и користити `LEFT JOIN` ка стадионима.\
Тако чувамо клуб, а колоне за стадион остају празне (`NULL`).

3. Колико голова је постигнуто главом (`body_part = 'head'`) у свакој сезони (`group by season`)? Рачунајте и аутоголове.

```sql
SELECT m.season, COUNT(*) AS headers
FROM match_events e 
JOIN matches m ON e.match_id = m.match_id
WHERE e.body_part = 'head' 
  AND e.event_type IN ('goal', 'own_goal', 'penalty_goal')
GROUP BY m.season;
```

Спајамо догађаје са утакмицама да бисмо имали приступ сезони, а затим филтрирамо по делу тела и типу догађаја.

4. Који играчи су добили највише жутих картона у сезони 2024/25 (рачунајте и други жути) (`match_events`)?

```sql
SELECT p.player_id, p.first_name, p.last_name, COUNT(*) AS yellows
FROM match_events e
JOIN players p ON e.player_id = p.player_id
JOIN matches m ON e.match_id  = m.match_id
WHERE m.season = '2024/25' 
  AND e.event_type IN ('yellow_card', 'second_yellow')
GROUP BY p.player_id, p.first_name, p.last_name 
ORDER BY yellows DESC;
```

Овде спајамо три табеле да бисмо добили податке о догађају, играчу и сезони.

Зашто у GROUP BY стављамо и player_id поред имена и презимена?\
Ако се два играча зову исто (нпр. Марко Марковић), груписање само по имену би сабрало њихове картоне заједно!\
`ID` је једини прави уникатни идентификатор, док имена извлачимо само због читљивости извештаја.

5. Колико играча нема ни један ред у `player_match_stats`, односно никад нису били у саставу за утакмицу?

```sql
SELECT COUNT(*) FROM players p
LEFT JOIN player_match_stats s ON p.player_id = s.player_id
WHERE s.player_id IS NULL;
```

Узимамо све играче, покушавамо да их спаримо са статистиком, а затим филтрирамо само оне за које није пронађен запис.

Anti-Join шаблон: Како у SQL-у тражимо нешто што не постоји?\
Не можемо тражити податке у табели статистика ако их тамо нема.\
Уместо тога, узимамо табелу свих играча, правимо `LEFT JOIN` са статистикама (остављајући `NULL` тамо где нема поклапања)\
Затим у WHERE клаузули намерно тражимо те `NULL` вредности.\
Ово је најбољи начин да се нађу "сирочићи" у бази.

---

6. Који судија је судио највише утакмица у којима је досуђен пенал (дат или промашен)?

```sql
SELECT r.referee_name, COUNT(DISTINCT e.match_id) AS matches_with_penalty
FROM match_events e
JOIN matches  m ON e.match_id   = m.match_id
JOIN referees r ON m.referee_id = r.referee_id
WHERE e.event_type IN ('penalty_goal', 'penalty_miss')
GROUP BY r.referee_name 
ORDER BY matches_with_penalty DESC;
```

Бројимо јединствене утакмице по судији на којима се десио пенал.

Питање тражи број утакмица, а не број пенала.\
Ако на једној утакмици буду два пенала, обичан `COUNT(*)` би судији додао два бода.\
Коришћењем `COUNT(DISTINCT e.match_id)` осигуравамо да се једна утакмица рачуна само једном, без обзира на то колико пенала је досуђено на њој.

## Решења задатака - Други део

1. Ко је дао највише асистенција у сезони 2024/25? Пазите: асистент је у колони `related_player_id`

```sql
SELECT p.player_id, p.first_name, p.last_name, COUNT(*) AS assists
FROM match_events e
JOIN players p ON e.related_player_id = p.player_id
JOIN matches m ON e.match_id = m.match_id
WHERE m.season = '2024/25' 
  AND e.event_type IN ('goal', 'penalty_goal')
GROUP BY p.player_id, p.first_name, p.last_name 
ORDER BY assists DESC;
```

Спајамо `players.player_id` са `related_player_id` из табеле догађаја.

Навикли смо да спајамо `e.player_id = p.player_id`.\
Међутим, главни актер догађаја је стрелац, док је асистент споредни актер (`related_player_id`).\
Да бисмо извукли име асистента, морамо преусмерити `JOIN` на ту специфичну колону.\
Ово показује да се табеле не морају увек спајати преко колона са истим именом.

2. Колико голова су по сезонама дали нападачи (FW), везни (MF) и одбрамбени (DF) играчи?

```sql
SELECT m.season, p.position, COUNT(*) AS goals
FROM match_events e
JOIN players p ON e.player_id = p.player_id
JOIN matches m ON e.match_id  = m.match_id
WHERE e.event_type IN ('goal', 'penalty_goal')
GROUP BY m.season, p.position 
ORDER BY m.season, goals DESC;
```

Спајамо три табеле и вршимо двоструко груписање (`GROUP BY m.season, p.position`)\

3. Колика је укупна посета по граду стадиона? Који град је имао највише гледалаца?

```sql
SELECT s.city, SUM(m.attendance) AS total_crowd
FROM matches m 
JOIN stadiums s ON m.stadium_id = s.stadium_id
GROUP BY s.city 
ORDER BY total_crowd DESC;
```

Спајамо утакмице и стадионе да бисмо сабрали све посетиоце за сваки град (пошто град може имати више стадиона).

4. Који стадион није угостио ниједну утакмицу у сезони 2024/25? Пазите где пишете услов за сезону.

```sql
SELECT s.stadium_name
FROM stadiums s
LEFT JOIN matches m ON s.stadium_id = m.stadium_id AND m.season = '2024/25'
WHERE m.match_id IS NULL;
```

Користимо Anti-Join приступ (Задатак 5 из првог дела), али уз додатни услов у `ON` клаузули.\

Зашто услов иде у `ON`, а не у `WHERE`?\
Тражимо стадионе који немају утакмице у 24/25. Ако стадион нема такве утакмице, колона `m.season` ће бити `NULL`.\
Ако бисмо написали `WHERE m.season = '2024/25'`, база би проверавала да ли је `NULL = '2024/25'`, што је нетачно, и тај стадион би био обрисан из резултата!\
Зато услов стављамо у `ON`: тиме говоримо бази "покушај да спајиш само утакмице из 24/25, а ако их нема, сачувај стадион са `NULL` вредностима".\
Тек онда у `WHERE` тражимо те `NULL` вредности.

5. Решите питање 5 из Вежбе 1 још једном, али са RIGHT JOIN. Да ли добијате исти број?

```sql
SELECT COUNT(*) FROM player_match_stats s
RIGHT JOIN players p ON s.player_id = p.player_id
WHERE s.player_id IS NULL;
```

Резултат је исти.\
Иако је табела са статистикама наведена прва, `RIGHT JOIN` осигурава да се задрже сви играчи (десна табела), па логика anti-join-a остаје иста.

6. `CROSS JOIN` табела `referees` и `stadiums`: колико комбинација судија–стадион је могуће, а колико се заиста догодило у табели `matches`?

SELECT COUNT(*) FROM referees r CROSS JOIN stadiums s;

SELECT DISTINCT referee_id, stadium_id FROM matches;
