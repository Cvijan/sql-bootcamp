## Увод у прозорске функције (Window Functions)

- Прозорске функције представљају један од најмоћнијих концепта у SQL-у
- За разлику од обичних агрегатних функција (`SUM`, `COUNT`, `AVG`) које заједно са `GROUP BY` клаузулом сабијају (групишу) више редова у један резултат, прозорске функције задржавају оригиналне редове, али им додају израчунату вредност која узима у обзир и друге редове

Замислите да гледате кроз "прозор" тренутног реда у друге редове који су са њим логички повезани.

### Синтакса

- Функција се препознаје по кључној речи `OVER()`
- Унутар ње дефинишемо изглед тог прозора:
    - `PARTITION BY` - Дели податке у независне групе (слично као `GROUP BY`)
        - На пример, израчунавање просека посебно за сваку општину или укупна посећеност стадиона за мечеве неког тима
    - `ORDER BY` - Дефинише редослед редова унутар тог прозора, неопходно за функције рангирања или кумулативне збирове

### Најважније прозорске функције

- `ROW_NUMBER()` - додељује јединствени редни број сваком реду унутар партиције
- `RANK()` - додељује ранг. Ако постоје исте вредности, додељује им исти ранг, али прескаче следеће бројеве
    - нпр. `1, 2, 2, 4, 4, 4, 7`
- `DENSE_RANK()` - Слично као `RANK`, али не прескаче бројеве ако постоје исте вредности
    - нпр. `1, 2, 2, 3, 3, 3, 4`
- `NTILE(n)` - Дели редове унутар партиције на `n` једнаких делове
    - нпр. `NTILE(4)` дели податке у квартиле (4 једнака дела)

### QUALIFY

- Као што `WHERE` филтрира редове, а `HAVING` филтрира групе након агрегације
- `QUALIFY` филтрира резултате након извршавања прозорских функција
    - `QUALIFY` подржавају модерни дијалекти SQL-а који се баве великим подацима
    - У традиционалним базама ово се решава паковањем упита у `CTE` и коришћењем `WHERE` клаузуле над `CTE`

1. Колико бирачких места има у свакој општини? Која општина има највише?

```sql
SELECT opstina, COUNT(*) AS mesta
FROM parlamentarni_izbori
GROUP BY opstina
ORDER BY mesta DESC;
```

Бројимо редове (бирачка места) за сваку појединачну општину.\
Резултат сортирамо како бисмо добили оне са највише места.

2. Колика је укупна излазност у целој табели?

```sql
SELECT ROUND(100 * SUM(glasali_biraci) / SUM(upisani_biraci), 2) AS izlaznost
FROM parlamentarni_izbori;
```

Питање наглашава "Рачунајте из сабраних бројева, не као просек излазности места".\
Замислите два бирачка места:\
На првом је гласало 1 од 2 бирача (50%)\
На другом 1000 од 1000 (100%)\
Просек два процента је 75%, али је стварна излазност скоро 100% (само 1 од 1002 није дао свој глас)

Зато ове односе увек рачунамо користећи `SUM(x) / SUM(y)`

3. Колико је гласова добила свака листа и колики је то удео у свим важећим гласовима? Прикажите првих пет листа.

```sql
SELECT lista, SUM(glasovi) AS glasovi,
       ROUND(100 * SUM(glasovi) / SUM(SUM(glasovi)) OVER (), 2) AS udeo_pct
FROM glasovi
GROUP BY lista
ORDER BY glasovi DESC
LIMIT 5;
```

Како у истом реду да прикажемо  гласове једне листе, али и њен проценат у односу на све?\
Прво `GROUP BY lista` сабирагласове за појединачну листу (`SUM(glasovi)`)\
Затим `SUM(SUM(glasovi)) OVER ()` узима те  групне збирове и сабира их на нивоу целог резултата (без партиција)\
Тиме добијамо укупан збир свих гласова у бази.

```sql
-- Без `window` функција
SELECT lista, 
       SUM(glasovi) AS glasovi,
       ROUND(100.0 * SUM(glasovi) / (SELECT SUM(glasovi) FROM glasovi), 2) AS udeo_pct
FROM glasovi
GROUP BY lista
ORDER BY glasovi DESC
LIMIT 5;
```

Да бисмо израчунали укупан број гласова користимо подупит (скаларни)\
`(SELECT SUM(glasovi) FROM glasovi), 2)` се извршава независно и враћа нам један број - укупан збир свих гласова у целој табели.\
Затим  се тај број користи као константа у нашем изразу, за сваку појединачну групу (`GROUP BY lista`)

Шта је боље?\
Решење са подупитом је често интуитивније за читање, међутим решење са прозорском функцијом `SUM(SUM(glasovi)) OVER ()`\
је технички елегантније јер база не мора поново да чита целу табелу да би израчунала укупан збир\
Уместо тога само сабере већ израчунате међузбирове тренутног `GROUP BY` резултата.

Ово је нарочито важно код великих табела, када се број редова мери милијардама.

4. Колико бирачких места има мање од 100 уписаних бирача?

```sql
SELECT COUNT(*) 
FROM parlamentarni_izbori 
WHERE upisani_biraci < 100;
```

5. Која општина има највећи, а која најмањи удео неважећих листића? Рачунајте само општине са бар 1.000 листића.

```sql
SELECT 
    opstina, 
    ROUND(100 * SUM(nevazeci_listici) / SUM(listici_u_kutiji), 2) AS nevazeci_pct
FROM parlamentarni_izbori
GROUP BY opstina
HAVING SUM(listici_u_kutiji) >= 1000
ORDER BY nevazeci_pct DESC; -- ASC/DESC за тражење најмањег/највећег удела
```

Пошто филтрирамо агрегирану вредност (укупан број листића на нивоу општине)\
Услов мора ићи у `HAVING` након груписања.
